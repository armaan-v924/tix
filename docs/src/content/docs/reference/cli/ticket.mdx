Create, inspect, and manage ticket workspaces

```sh frame="none"
tix ticket <COMMAND>
```


## `tix ticket add`

Add repository worktrees to a ticket

```sh frame="none"
tix ticket add [OPTIONS] <REPO_ALIASES>...
```


Also available as `tix add` — the same command, spelled without the group.

### Arguments

| Argument | Description |
| --- | --- |
| `<REPO_ALIASES>...` | Registered repository aliases to add |

### Options

| Option | Description |
| --- | --- |
| `-t, --ticket <TICKET>` | The ticket to act on: a bare id resolved under the tickets directory, or a path (anything containing a separator, or `.`/`..`). Discovered by walking up from the current directory when omitted |
| `-p, --project <NAME>` | The project a bare ticket id resolves in. Inferred from the current directory when omitted; with a path or a discovered ticket, asserts the ticket belongs to it |
| `-b, --branch <BRANCH>` | Branch for the new worktree(s); derived from `[defaults]` + ticket context when omitted, and required when the derived branch is taken |
| `--as <NAME>` | Directory name for the new worktree, defaulting to the repository alias; required when a worktree already holds that name |
| `--base <REFISH>` | What a new branch is cut from: a branch name (local or origin's, whichever is ahead), or any ref, tag, or SHA. Defaults to each repository's own default branch on origin |


## `tix ticket destroy`

Destroy a ticket: prune its worktrees, delete its directory

```sh frame="none"
tix ticket destroy [OPTIONS] [TICKET]
```


Also available as `tix destroy` — the same command, spelled without the group.

### Arguments

| Argument | Description |
| --- | --- |
| `[TICKET]` | The ticket to destroy (id under the tickets directory, or a path); discovered from cwd when omitted |

### Options

| Option | Description |
| --- | --- |
| `-t, --ticket <TICKET>` | The ticket to act on: a bare id resolved under the tickets directory, or a path (anything containing a separator, or `.`/`..`). Discovered by walking up from the current directory when omitted |
| `-p, --project <NAME>` | The project a bare ticket id resolves in. Inferred from the current directory when omitted; with a path or a discovered ticket, asserts the ticket belongs to it |
| `-f, --force` | Skip confirmation, force-prune (discarding uncommitted changes), and delete the ticket directory even if pruning fails |
| `--dry-run` | Print what would be pruned and deleted, and what would stop the destroy, without asking or touching anything; exits non-zero where the real run would fail. Combine with --force to preview a forced destroy |

## `tix ticket setup`

Create a new ticket workspace with worktrees

```sh frame="none"
tix ticket setup [OPTIONS] <TARGET> [REPO_ALIASES]...
```


Also available as `tix setup` — the same command, spelled without the group.

### Arguments

| Argument | Description |
| --- | --- |
| `<TARGET>` | Where the ticket goes: a bare key (e.g. JIRA-123) created under the tickets directory, or a path (anything containing a separator, or `.`/`..`) created at that location |
| `[REPO_ALIASES]...` | Repositories to include (defaults to `[defaults].repositories`) |

### Options

| Option | Description |
| --- | --- |
| `-k, --key <KEY>` | The key recorded for the ticket, defaulting to the directory name. Path form only — a bare key already names itself |
| `-p, --project <NAME>` | The project to create the ticket in, created on first use. Inferred from the current directory when omitted; outside any project the ticket is loose. Key form only — a path already says where it goes |
| `-d, --description <DESCRIPTION>` | Human-readable description; feeds branch name derivation |
| `--base <REFISH>` | What each new branch is cut from: a branch name (local or origin's, whichever is ahead), or any ref, tag, or SHA. Defaults to each repository's own default branch on origin |
| `-a, --all` | Include every registered repository |
