## Prebuilt binaries

<Tabs syncKey="os">
<TabItem label="macOS (Apple Silicon)">
<Code
  lang="sh"
  code={`mkdir -p ~/.local/bin
curl -fsSL ${base}/tix-${release.tag}-macos-aarch64.tar.gz | tar -xz -C ~/.local/bin tix`}
/>
Make sure `~/.local/bin` is on your `PATH`.
</TabItem>

<TabItem label="Linux (x86_64)">
<Code
  lang="sh"
  code={`mkdir -p ~/.local/bin
curl -fsSL ${base}/tix-${release.tag}-linux-x86_64.tar.gz | tar -xz -C ~/.local/bin tix`}
/>
Make sure `~/.local/bin` is on your `PATH`.
</TabItem>

<TabItem label="Windows (x86_64)">
<Code
  lang="powershell"
  code={`Invoke-WebRequest ${base}/tix-${release.tag}-windows-x86_64.zip -OutFile tix.zip
Expand-Archive tix.zip -DestinationPath "$HOME\\AppData\\Local\\Programs\\tix" -Force
Remove-Item tix.zip`}
/>
Add `%LOCALAPPDATA%\Programs\tix` to your `PATH` to finish.
</TabItem>
</Tabs>

Check it runs:

```sh
tix --version
```

## From source

Needs a Rust toolchain.

```sh
git clone https://github.com/armaan-v924/tix
cargo install --path tix/tix-cli
```

## Staying up to date

```sh
tix cli update
```

It lists tix's releases on GitHub and installs the newest one **in the major
version you are running**: tix 3.3.0 moves to 3.3.1 or 3.4.0, never to 4.0.0
on its own. Drafts and prereleases are ignored. If you are already current it
stops; otherwise it downloads the asset for your platform, verifies its
checksum, and replaces the binary **in place** — the executable you ran it
from.

A new major version always means what is on disk changed, so the new binary
cannot use your config and tickets until you run `tix migrate`. When one is
out, `tix cli update` tells you, with a link to its release notes, and only
installs it with your consent:

- In a terminal, it asks. Declining still installs the newest release in
  your current major.
- With `--major`, it installs the newest release of any major without asking.
- Without a terminal (scripts, CI) and without `--major`, it installs the
  in-major update if there is one, then **exits non-zero** naming the flag,
  so automation never crosses a major silently.

```sh
tix cli update --dry-run   # report the update and any skipped major, download nothing
tix cli update --major     # cross into a new major; run `tix migrate` next
```

<Aside type="tip">
If `tix` lives somewhere you cannot write to, set `TIX_INSTALL_PATH` to say
where the new binary should go instead.
</Aside>

## Shell completions

`tix completions` writes a completion script to standard output for `bash`,
`zsh`, `fish`, `elvish`, or `powershell`. It is the one command that works
before any config exists.

<Tabs syncKey="shell">
<TabItem label="zsh">
```sh
tix completions zsh > "${fpath[1]}/_tix"
```
</TabItem>
<TabItem label="bash">
```sh
tix completions bash > ~/.local/share/bash-completion/completions/tix
```
</TabItem>
<TabItem label="fish">
```sh
tix completions fish > ~/.config/fish/completions/tix.fish
```
</TabItem>
<TabItem label="powershell">
```powershell
tix completions powershell | Out-String | Invoke-Expression
# To persist, append the same line to $PROFILE
```
</TabItem>
</Tabs>

Start a new shell afterwards.
