The whole loop once: set tix up, register a repository, open a ticket, tear
it down. All of it is reversible.

## Create the config

Nothing works until this file exists.

```sh
tix config init
```

It asks two questions, each with a default:

```
Tickets directory [/home/you/tickets]:
Code directory (where repos are cloned) [/home/you/code]:
```

<Aside type="tip">
Edit the file by hand whenever you like — tix rewrites only the values it
touches, so comments and layout survive. Every key is listed in the
[configuration reference](../../reference/configuration/).
</Aside>

## Register a repository

tix only manages repositories you have told it about.

```sh
tix repo add my-org/api    # full URL, owner/repo, or bare repo
tix repo clone --all       # clone every registered repo not already on disk
```

The alias — how you refer to it from now on — defaults to the repository
name, here `api`. Pass `--alias` to choose another.

A registered repository stays available to every ticket.

## Open a ticket

```sh
tix setup JIRA-123 --description "Fix the login bug" api
```

<FileTree>
- ~/tickets/JIRA-123
  - .tix
    - ticket.toml
  - api
</FileTree>

`api` is a [git worktree](../../concepts/worktrees-and-branches/) of your
`~/code/api` checkout, on a new branch derived from the key and description.
Your original checkout has not moved.

Naming no repositories uses `[defaults].repositories`; `--all` uses every
registered one.

## Work

```sh
cd ~/tickets/JIRA-123/api
```

An ordinary checkout — commit, push, open a review. tix records the branch
name and stays out of the way.

Commands work from anywhere inside the ticket, at any depth:

```sh
tix info      # this ticket: worktrees, branches, status
tix list      # every ticket you have
```

From outside, name it: `tix info --ticket JIRA-123`.

<Aside type="caution">
A bare name is always looked up in your tickets directory. Sitting next to a
ticket directory, write `--ticket ./JIRA-123` — see
[Ticket discovery](../../concepts/ticket-discovery/).
</Aside>

## Add and remove repositories

Work spreading to another repository does not need a new ticket:

```sh
tix add web        # add a worktree for `web`
tix remove web     # prune it; the rest of the ticket is untouched
```

## Tear it down

```sh
tix destroy JIRA-123
```

Confirms, prunes every worktree, removes the directory. If any worktree has
uncommitted changes it stops and leaves everything alone — commit, stash, or
push first.

`--force` skips the confirmation, discards uncommitted changes, and deletes
the directory even if pruning fails.

Branches and commits survive either way.
