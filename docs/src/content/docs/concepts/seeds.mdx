Values in `[defaults]` are **seeds**. They are read once, when a ticket or
worktree is created, and the result is written into the ticket document.
Changing one later affects only what you create afterwards.

<Aside type="caution" title="There is no fallback resolver">
tix never consults `[defaults]` at read time. A ticket's branch is whatever
its `.tix/ticket.toml` says — not "the config value, unless overridden".
</Aside>

## What that looks like

```sh
tix setup JIRA-123              # branch: feature/JIRA-123
# ...change branch_prefix to "fix"...
tix info JIRA-123               # branch: feature/JIRA-123 — unchanged
tix setup JIRA-456              # branch: fix/JIRA-456
```

The first branch keeps its name. It is a real git branch, possibly pushed,
possibly with a review open against it. Anything that shapes state on disk
has to be captured at creation, because a config file cannot retroactively
rewrite what git already did.

## The seed fields

| Field | Seeds | Read at |
| --- | --- | --- |
| `branch_prefix` | Branch name derivation | `tix setup`, `tix ticket add` |
| `repositories` | Which repositories a new ticket includes | `tix setup` |
| `default_repository_owner` | Remote URL construction | `tix repo add` |
| `github_base_url` | Remote URL construction | `tix repo add` |

`[defaults].repositories` and a ticket's worktree list are not an override
pair: the first is what to seed a *new* ticket with, the second is what a
ticket has.

## Changing an existing ticket

Config will not do it, so do it directly:

```sh
tix add web                              # add a repository
tix add web --branch fix/JIRA-123-retry  # with a branch you choose
```

`tix ticket add` re-derives the branch name **at add time**, against
whatever `branch_prefix` says now. A worktree added after you changed the
prefix will not match its siblings — hence `--branch`.

To rename a branch that exists, use git. tix records what git tells it.
