Troubleshooting

Every error tix prints goes to standard error, prefixed error:, and exits 1.

No config

Section titled “No config”

Nothing works before the config exists. If you have one and tix disagrees, it is looking somewhere else — --config beats TIX_CONFIG_PATH beats the platform default. tix config show --config <path> confirms which file it read.

The file exists but is missing tickets_directory / code_directory. Add the section by hand or re-run init with --force.

Not inside a ticket

Section titled “Not inside a ticket”

The upward walk found no .tix/ticket.toml. Either you are outside any ticket, or you are next to one rather than inside it — a bare --ticket NAME is looked up in your tickets directory, so a ticket in the current directory needs --ticket ./NAME.

Unknown repository or worktree

Section titled “Unknown repository or worktree”

Aliases come from tix repo add. The message lists everything tix knows.

tix remove addresses the worktree directory name in the ticket, which is not necessarily a repository you expect to be there. tix info lists them.

Already exists

Section titled “Already exists”

tix will not create over an existing ticket. Use it, or destroy it first.

One worktree per repository per ticket, for now.

Invalid ticket key

Section titled “Invalid ticket key”

A key becomes a directory name under your tickets directory, so / and \ are rejected. Everything else is allowed — REL-1.2.3 is a fine key.

Remove refused a worktree

Section titled “Remove refused a worktree”

Untracked files count. Commit or stash them and retry, or pass --force if you mean to throw them away.

Destroy stopped part way

Section titled “Destroy stopped part way”

Almost always uncommitted changes. Commit, stash, or push, then retry. Worktrees already pruned stay pruned and the ticket document is kept in step, so a retry resumes.

With --force, pruning failures become warnings and the directory is deleted regardless. That can leave registrations behind in the source repositories:

Run that in the source repository under your code directory.

Worktrees flagged in tix info

Section titled “Worktrees flagged in tix info”

The ticket document records a worktree that is gone or is no longer a git checkout — usually something deleted by hand. tix remove <name> drops the entry, prunes the source repository’s stale registration if git still has one, and warns:

A directory that is still there but no longer a checkout is left in place — tix cannot tell whether it holds work. Move what you need out of it and delete it yourself. Add the worktree back with tix add <alias> if you still want it.

tix destroy handles a missing worktree the same way. It refuses one that is not a git repository, since deleting the ticket would delete it unchecked, unless you pass --force.

Unknown command

Section titled “Unknown command”

A typo, or a plugin that is not on your PATH. tix --help lists the plugins tix can currently find.

Seeing what tix did

Section titled “Seeing what tix did”

By default tix prints one line per action (a clone, a worktree created or removed) and labels anything that went wrong warning: or error:. To see every step, pass -v (or --log-level debug for slightly less):

The detailed format adds timestamps, levels, and the module each line came from, which helps when you report a bug.

Conflicting log flags

Section titled “Conflicting log flags”

They set the same thing. Pick one.
