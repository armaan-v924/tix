2//! The context-and-consistency layer shared by `tix-cli` and plugins.
3//!
4//! `tix-sdk` is deliberately coupled to `tix-cli`: it is the CLI's own
5//! context layer, shipped as a crate so plugins inherit identical behavior
6//! for free. Surface grows by **promotion from `tix-cli`** — a helper the
7//! CLI wants applied consistently moves here — never by speculation about
8//! plugin needs.
9//!
10//! What lives here:
11//!
12//! - [`context`] — global config path resolution
13//!   (`--config` > `TIX_CONFIG_PATH` > platform default).
14//! - [`discovery`] — the ticket walk and `--ticket` override semantics.
15//! - [`document`] — the format-preserving TOML document layer: generic
16//!   parse, typed section extraction, atomic locked writes.
17//! - [`delta`] — diff-back config deltas: the plugin write helper and the
18//!   host's JSON→TOML apply mechanics.
19//! - [`host`] — the plugin side of the invocation contract: `--tix-*` flag
20//!   parsing and the protocol check ([`host::PROTOCOL`]; the version →
21//!   change table is published with the
22//!   [plugin documentation](https://tix.armaanv.dev/latest/plugins/protocol/)).
23//! - [`spawn`] — nested `tix` invocations pinned to the current ticket.
24//! - [`state`] — plugin state directories, created lazily.
25//! - [`SdkError`] — the SDK's error type; document parse/serialize errors
26//!   live here, not on the engine.
27//!
28//! `tix-engine` is re-exported wholesale (tokio/axum style): depend on
29//! `tix-sdk` alone and reach engine types as `tix_sdk::Ticket`,
30//! `tix_sdk::RepositoryConfig`, and so on. Frontends that want no tix
31//! layout policy may still depend on `tix-engine` directly.
32
33pub mod context;
34pub mod delta;
35pub mod discovery;
36pub mod document;

38pub mod error;
